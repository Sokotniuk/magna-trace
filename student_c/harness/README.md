# harness/ — временная замена Copilot (OpenAI + MCP)

**Владелец:** C. **Статус:** инструмент разработки. Не интерфейс продукта и не доказательство G0.

## Зачем

Среда Copilot Studio `tuke.sk (default)` без кредитов (`EnforcementUsageCredits`), а свою создать нельзя. Чтобы не стоять, диалог ведёт модель OpenAI. Всё остальное построено так, как будет у Copilot:

```
Сейчас:   техник → harness/chat_openai.py (OpenAI) ─┐
                                                     ├─► /mcp (B) → те же функции → Oracle
Потом:    техник → Copilot Studio agent ─────────────┘
```

| Часть | Сейчас | После перехода на Copilot |
| --- | --- | --- |
| Инструкции агента | `copilot/instructions.md` → системный промпт | тот же текст → поле Instructions в Copilot Studio |
| Инструменты и их описания | MCP-сервер B (`/mcp`), описания из `copilot/tool_descriptions.md` | тот же сервер, подключён через `+ Add → MCP` |
| Авторизация | заголовок `X-API-Key` | тот же заголовок в подключении Copilot Studio |
| Логика, данные, evidence | бэкенд B и A | без изменений |
| `harness/` | используется | не используется |

Правило: **в `harness/` нет никакой логики продукта.** Только передача сообщений между моделью и MCP-сервером. Всё, что должно работать и в Copilot, живёт в `/mcp` или в `instructions.md`.

## Запуск

1. Бэкенд B запущен, `/mcp` отвечает локально.
2. Установить зависимости (в отдельном виртуальном окружении):

```bash
pip install -r harness/requirements.txt
```

3. Задать переменные окружения в своём терминале (не в файлах репозитория):

| Переменная | Значение |
| --- | --- |
| `TRACE_MCP_URL` | `http://127.0.0.1:8000/mcp` — локально, туннель не нужен |
| `TRACE_API_KEY` | ключ бэкенда (новый, после замены утёкшего) |
| `TRACE_API_KEY_HEADER` | `X-API-Key` (по умолчанию) |
| `OPENAI_API_KEY` | ключ OpenAI |
| `OPENAI_MODEL` | модель OpenAI с поддержкой вызова инструментов |

4. Запустить:

```bash
python harness/chat_openai.py
```

В консоли видно каждый вызов инструмента и `request_id` — его можно сверить с логом B.

## Правила

- **Ключ OpenAI принадлежит другу.** Только переменная окружения; не в репозитории, не в чатах, не в логах. Попроси друга поставить лимит расходов в аккаунте OpenAI.
- **Данные.** Пока `health_echo` возвращает только число строк, данные MAGNA никуда не уходят. Как только `open_case` начнёт отдавать реальные измерения, они пойдут в OpenAI. До этого — одно сообщение организаторам: можно ли отправлять эти данные в OpenAI во время разработки.
- **Честная маркировка.** Если на демо показывается этот харнесс, он называется «временный клиент на OpenAI, Copilot заблокирован кредитами». Выдавать его за Copilot нельзя: по `product.md` v1.4 он Copilot не заменяет.
- **Совпадение поведения.** Не правь `instructions.md` или описания инструментов под особенности GPT. Если GPT ведёт себя не так, как должен Copilot, — исправляй текст так, чтобы он был правильным для обоих.

## Переход на Copilot (когда появятся кредиты)

1. В Copilot Studio: Instructions ← содержимое `copilot/instructions.md`.
2. `+ Add → MCP`: адрес туннеля + `/mcp`, API key, Header, `X-API-Key`, подключение с текущим ключом.
3. Убрать Work IQ и Search all websites, Memory выключена.
4. Прогнать в Preview те же сценарии, что прогонялись здесь (C7). Сверить `request_id` с логом B — это G0 и G2.
5. `harness/` остаётся в репозитории как инструмент отладки, на демо не используется.

## Проверено / не проверено

- Код не запускался: на машине автора не было Python и работающего `/mcp`.
- Имена в MCP SDK (`streamablehttp_client`, `ClientSession`) соответствуют официальному Python SDK, но сверь их с установленной версией.
- Вызов из Copilot Studio через этот MCP-сервер не проверен — платформа заблокирована кредитами.
