# C → B: подключение к Copilot через MCP вместо REST

> **От:** студент C (Copilot и интеграция) · **Кому:** студент B (бэкенд) · 2026-11-10
> **Срочность:** влияет на G0 (H+6). Нужен ответ «согласен / есть возражения» в течение 15 минут.

## 1. Проблема

Мы планировали импортировать в агента Copilot Studio файл `openapi.v2.json` как REST-инструмент. В нашем тенанте это невозможно. Что я проверил:

| Что | Результат |
| --- | --- |
| `Add a tool` → `+ Add` | Предлагает только **Model Context Protocol (MCP)** и **Workflow** |
| Импорт REST API / OpenAPI | Нет |
| Свой Custom connector во вкладке Connectors | Нет |
| Форма MCP | Поля: имя, описание, **Server URL**; авторизация: **None / API key / OAuth 2.0** |

Workflow (Power Automate с HTTP-запросом к нашему API) отбросил: лишнее звено, задержка, возможная лицензия.

## 2. Решение

**Агент подключается к бэкенду как к MCP-серверу с авторизацией по API key.**

**Не меняется:**

- пять инструментов и их имена: `open_case`, `get_evidence`, `record_answer`, `get_handover`, `list_stations`;
- входные поля, конверт ответа, коды ошибок, evidence IDs, `request_id`;
- Oracle, `measurements.py`, `evidence.py`, `cases.py`, `diagnostics.py` — вся логика;
- REST-эндпоинты `/api/v1/...` остаются: на них работает дашборд D и тесты.

**Меняется:** появляется второй вход — `/mcp`. Он вызывает **те же функции сервисного слоя**, что и REST-роуты.

```
Copilot Studio ──MCP + API key──► /mcp ──┐
                                         ├──► те же функции (cases, evidence, diagnostics, oracle_repo)
Dashboard (D) ──REST + proxy key──► /api/v1 ──┘
```

## 3. Что нужно сделать

### Шаг 1 — `health_echo` для G0, срочно (до H+4)

Один MCP-инструмент `health_echo`, который возвращает:

```json
{ "request_id": "…", "retrieved_at": "…", "status": "ok",
  "data": { "measurement_rows": "<COUNT(*) из Oracle через функцию A>" } }
```

С ним G0 проверяется так же, как планировали: два вызова из чата, `request_id` совпадает с твоим логом, число совпадает с ручным `COUNT(*)` у A.

### Шаг 2 — пять инструментов (к H+14, вместе с B6)

| MCP-инструмент | Вызывает то же, что | Аргументы |
| --- | --- | --- |
| `open_case` | `POST /cases` | `station_number`; необязательные `from`, `to`, `serial_number` |
| `get_evidence` | `GET /cases/{case_id}/evidence/{evidence_id}` | `case_id`, `evidence_id` |
| `record_answer` | `POST /cases/{case_id}/answers` | `case_id`, `question_id`, `answer_text` |
| `get_handover` | `GET /cases/{case_id}/handover` | `case_id` |
| `list_stations` | `GET /stations` | необязательные `q`, `limit` |

`health_echo` после G0 убрать или оставить только в режиме разработки.

## 4. Требования

| # | Требование | Почему |
| --- | --- | --- |
| 1 | Транспорт **streamable HTTP**, путь `/mcp` | Форма просит один URL вида `https://…/mcp`. Совместимость подтвердит первый вызов, заранее не гарантирую |
| 2 | **Ключ в заголовке проверяется на каждом запросе к `/mcp`**; без ключа или с неверным — отказ, до вызова любого инструмента | Публичный туннель. `None` в форме не выбираем |
| 3 | Имя заголовка — предварительно `X-API-Key`. Окончательное сообщу после пробного подключения | Не знаем точно, как Copilot Studio его передаёт |
| 4 | Инструменты вызывают сервисные функции **напрямую**, а не через HTTP-запрос к собственному REST | Без дублирования логики и лишних сбоев |
| 5 | Ответ инструмента — **тот же конверт**, что у REST. Ошибки возвращаются конвертом со `status: "error"` и кодом, а не исключением | Агент должен видеть `NO_DATA`, `CASE_NOT_FOUND_OR_EXPIRED` и т.д. и сообщать о них честно |
| 6 | Десятичные числа — строками | Как в REST; точность не теряется |
| 7 | `request_id` в каждом ответе и в логе, ключ в логе не пишется | Доказательство для G0 |
| 8 | Только **tools**. Без MCP resources, prompts, sampling | Скоуп |
| 9 | Один воркер, как и раньше | Случаи в памяти |
| 10 | Сервер не хранит состояние MCP-сессий: состояние случая живёт в `cases.py` и передаётся через `case_id` | Туннель и перезапуски не ломают диалог сильнее, чем сейчас |

## 5. Набросок (проверь по своей версии SDK)

Ниже — ориентир на официальном MCP SDK для Python (пакет `mcp`). Названия API менялись между версиями, поэтому сверься с установленной; это не готовый код.

```python
# backend/app/mcp_server.py  — владелец B
from mcp.server.fastmcp import FastMCP
from . import services  # те же функции, что вызывают REST-роуты

mcp = FastMCP("MAGNA TRACE", stateless_http=True)

@mcp.tool(description=DESCRIPTIONS["open_case"])   # текст описаний даёт C
def open_case(station_number: str, from_: str | None = None,
              to: str | None = None, serial_number: str | None = None) -> dict:
    return services.open_case(station_number, from_, to, serial_number)  # конверт
```

```python
# backend/app/main.py
app = FastAPI(lifespan=...)          # MCP session manager должен быть запущен в lifespan
app.mount("/", mcp.streamable_http_app())   # даёт путь /mcp
# + middleware: для пути /mcp без верного X-API-Key → 401
```

Учти: имя `from` — зарезервированное слово Python, поэтому в сигнатуре нужен другой идентификатор. Как он будет называться для агента, реши сам и скажи мне — я пропишу это в описаниях.

## 7. Как проверим (критерии готовности)

**Для G0 (H+6):**

- [ ] `POST /mcp` без ключа → отказ; с ключом → ответ.
- [ ] Copilot Studio видит сервер и инструмент `health_echo`.
- [ ] Вызов из Preview: `request_id` в чате совпадает с твоим логом.
- [ ] Второй вызов: `measurement_rows` совпадает с ручным `COUNT(*)` у A.

**Для G2 (H+16):**

- [ ] Агент видит все пять инструментов.
- [ ] REST и MCP на одинаковый вход возвращают одинаковый `data` (один тест на инструмент).
- [ ] Ошибки приходят конвертом с кодом, без подставных данных.
- [ ] Агент сам вызывает `record_answer` после ответа техника (это проверяю я).
