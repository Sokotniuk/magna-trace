# Проверка общей сборки на реальных системах

Эта инструкция для уполномоченной команды. В облачной сессии нет Oracle credentials, источника, frontend D и нового исполнителя C. Галочки ниже заполняются только после фактической проверки.

- [ ] На утверждённом Oracle host установить сборку, проверить hashes и SELECT-only доступ. Не расширять grants и не публиковать Oracle listener.
- [ ] Выполнить независимые SELECT из согласованного пакета A4, который находится у команды. Сверить свежий COUNT и минимум три значения/границы hand arithmetic; подобрать реальный scope. Исторические числа A не являются вечными assertions.
- [ ] Поднять backend из корня с одним worker и серверными credentials, временно TRACE_DEV_ROUTES=true. healthz → 200, readyz → 200 только после настоящего COUNT.
- [ ] Запустить python -m student_b.live_check --station VERIFIED_STATION --check-echo --expected-count FRESH_INDEPENDENT_COUNT. Записать команду без секретов, hashes сборки, результаты и request IDs. Клиент создаёт два явно тестовых RAM-кейса; служебные сообщения не являются реальными сообщениями техника.
- [ ] Независимо сверить выбранные OBSERVED/CALCULATED с A4 SQL и точностью A3; отдельно проверить equality/code 1001 без PASS/FAIL вывода. Сохранять строки локально, не в Git.
- [ ] Провести source unavailable/timeout проверки в отдельном утверждённом test configuration. Не останавливать общую базу. Кодовая проверка driver doubles уже есть; она не заменяет runtime evidence.
- [ ] C подключает свой выбранный API/провайдер через авторизованный HTTPS и server-side key, проверяет актуальные пути/схему; ключ не попадает в браузер/промпт/лог. Любая спецификация C должна соответствовать фактическому runtime B2. Внешние инструменты C здесь не предоставлены.
- [ ] D подключает frontend через server-side proxy, проверяет case_id=null у станций, data snapshot без wrapper, nullable deviation и принятые search/time semantics.
- [ ] Дважды пройти весь пользовательский диалог с реальным C: case → ≥3 факта с evidence → вопрос → самостоятельный вызов record_answer после ответа → обновлённый шаг → handover. Сверить request IDs/логи. Две формулировки ответа техника.
- [ ] С C определить явный подтверждённый conflict flow. Внутренний review работает; нового публичного поля B2 нет. Поздний review не переписывает immutable evidence.
- [ ] Отключить dev routes, перезапустить и убедиться, что echo/docs/openapi закрыты. Завершить согласование D15, общего бюджета коннектора и ограничений среды. Только команда отмечает G0–G3/A8/backend DoD.
