# B → C: необязательная проверка бюджета вызовов

Передайте C эту папку или usage_gate.py вместе с данным описанием. Автоматическая отправка C не выполняется.

usage_gate.py — исходный присланный файл без правок. Он принимает JSON журнала и возвращает решение о следующем управляемом шаге. Сам он не делает API-запросов, не получает статистику провайдера, не останавливает текущий запрос и не знает лимит подписки ChatGPT.

Проверить синтетический формат:

```bash
python devtools/student_b/usage_gate.py devtools/student_b/examples/usage-record.json
```

Ожидается ALLOW_NEXT_CONTROLLED_STEP, 100 входных/20 выходных токенов и оценка 0.01 USD. Это вымышленные значения, не тариф и не реальный расход.

Если C решит применять утилиту, его исполнитель вызовов должен:

1. Передать явные provider, model и локальный endpoint_alias, без ключей и URL с секретами. Добавлять реальную статистику после каждого вызова; неизвестные значения передавать null.
2. Проверять поле decision перед следующим вызовом. SOFT_STOP запрещает следующий шаг; ошибка валидации тоже должна остановить исполнение. CLI возвращает 0 и при SOFT_STOP: проверка только exit code недостаточна.
3. Для неизвестной стоимости использовать cost_usd=null, cost_provenance=unknown, price_source=null. При ненулевом числе шагов и заданном soft cap неизвестная стоимость приводит к остановке.
4. Общий timeout, отмену текущего запроса и ограничения провайдера реализовать в своём исполнителе. Это post-step soft stop; один вызов может превысить бюджет. С нулём шагов денежный cap сам по себе не запрещает первый вызов. Полнота журнала не проверяется; отдельного token cap нет.

Не добавлять LLM-слой в FastAPI B. Не менять B2 ради служебной статистики. Перед реальным подключением C нужны подтверждённые SDK response fields, тариф/источник цены, timeout/cancellation и политика ошибок. До этого утилита остаётся offline-примером.
